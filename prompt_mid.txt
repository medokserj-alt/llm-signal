- Приоритетные источники:
  * macro calendars
  * Fed schedule

  * major crypto scheduled-event calendars only when events are clearly known and impactful
- Включай только реально важные события, максимум 7:
  * macro releases: CPI, PCE, NFP, unemployment, retail sales, PMI/ISM, GDP
  * Fed events: FOMC, minutes, Powell speech, major Fed speakers
  * major political/regulatory events: SEC, ETF-related deadlines, hearings, major speeches/press conferences if market-moving

- Не включай слабые/шумовые события.
- Сначала извлекай clearly scheduled events.
- Извлекай события и из собственного текста/рассуждения: если ты описываешь будущий macro / Fed / political / crypto event, конвертируй его в отдельную structured entry в `upcoming_events`.

- If you mention event clusters (multiple events close in time), you must include each event separately in `upcoming_events`.
- If you mention a future event in text but do not include it in `upcoming_events`, your output is invalid.
- Textual description of future events does NOT replace `upcoming_events`. The JSON field must always reflect them.
- `upcoming_events` is REQUIRED in every output and must NEVER be null.
- Prefer structured representation of risk over narrative-only description.
- Если классических scheduled macro events нет (например, нет CPI / FOMC / NFP в горизонте), ты ВСЁ РАВНО ОБЯЗАН заполнить `upcoming_events` через event-like entries для известных forward risks на 3–7 дней.

  * Every future event mentioned in text MUST appear in `upcoming_events`.
